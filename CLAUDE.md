# CLAUDE.md — File Scanner (general reference)

Electron + plain JS desktop app: scans drives for doc/docx/xls/xlsx/pdf, indexes them in SQLite (FTS5), lists them in a virtualized table with OS icons, opens the file or its folder. Windows primary, Linux supported. Keep it simple; don't over-engineer.

## Layout
| File | Role |
|---|---|
| `main.js` | Window, IPC handlers, scan orchestration (worker lifecycle), shell/icon calls |
| `preload.js` | `contextBridge` → `window.api` (only whitelisted calls/events) |
| `db.js` | better-sqlite3 + FTS5; the ONLY place with SQL. Main process only |
| `settings.js` | settings.json in userData (whitelisted deep merge); main only |
| `skip-rules.js` | Skip groups per platform (user can include each in Settings) |
| `scanner-worker.js` | `worker_threads` directory walker; batches 500; skip rules passed in `workerData.skip` |
| `preview-worker.js` | Quick view parser (mammoth for docx, SheetJS for xls/xlsx, word-extractor for doc) in a worker thread |
| `updates.js` | New-version notification (GitHub latest release check; no auto-install) |
| `indexer.js` + `content-worker.js` | Content indexing (separate background task): pool of 2 worker threads extracting text from docx/doc/xlsx/xls/pdf |
| `locales/` | `ka.json` (default) and `en.json`; keep keys identical |
| `renderer/` | `index.html`, `core.js` (settings/i18n/tabs), `files.js` (list, tree, scan UI), `settings-ui.js`, `preview.js` (quick view panel), `index-ui.js` (content indexing UI), `update-ui.js` (update banner + About card), `styles.css`, `fonts/` |
| `build/` | `icon.png` + `icon.ico` (generated by `npm run icons` → `scripts/make-icon.js`) |
| `docs/` | Architecture notes (see below) |

## Commands
- `npm install` (postinstall rebuilds better-sqlite3 for Electron), `npm start`, `npm run dist[:win|:linux]`
- Plain `node` can't load better-sqlite3 (built for Electron ABI). To script it use `ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron script.js`.
- Gotcha: if `ELECTRON_RUN_AS_NODE` is set in the shell (VS Code terminal), the app crashes with `Cannot read properties of undefined (reading 'handle')`. Run with `env -u ELECTRON_RUN_AS_NODE`.
- Headless check on Linux: `xvfb-run -a node_modules/electron/dist/electron . --user-data-dir=<tmp>`.

## Rules / invariants
- Security: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, CSP in `index.html`. Never expose `ipcRenderer` or the DB to the renderer.
- Use `path` and `process.platform`; no hardcoded separators.
- Worker must call `parentPort.close()` when done, or the thread never exits.
- Rescan prunes only rows under the scanned roots with `scanned_at < scanStart`, and only when the scan was NOT stopped.
- Search: FTS5 trigram (terms ≥3 chars); shorter terms fall back to `LIKE`.
- New UI text: add the key to BOTH `locales/*.json`, use `data-i18n*` attributes or `App.t()`. Main sends error CODES (`missing`, `open`, `busy`, `nothing`), the renderer translates.
- New setting: add it to `DEFAULTS` in `settings.js` (unknown keys are dropped), read it via `App.settings`, save via `App.set(patch)`.
- New tab: one `.tab-btn` + one `<section class="tab" data-tab>` in `index.html`, a module registering with `App.onReady`.
- Dark/light: main sets `nativeTheme.themeSource`; CSS only uses `prefers-color-scheme`.
- `package.json > build.files` is a whitelist: any new top-level runtime file/folder MUST be added there or the packaged app breaks.
- Delete is ALWAYS `shell.trashItem` (never permanent). Main only trashes indexed files, or folders that contain indexed files and are not protected (`isProtectedDir` in main.js: roots, top-level system dirs, home, userData, Documents/Desktop/Downloads/...). Never add a permanent-delete path or a fallback to one.
- CSP blocks inline `style="..."` attributes: set styles from JS (`el.style.x`) or use classes.
- Quick view parses untrusted files ONLY in `preview-worker.js` (size cap 30 MB, 15 s timeout, 768 MB heap) and the renderer builds the result with DOM APIs / an allow-list sanitizer (`preview.js`); never `innerHTML` document content. `xlsx` is installed from the official SheetJS CDN tarball (the npm registry copy is outdated/vulnerable); do not switch it back to the registry version.
- Multi-select/multi-delete: the renderer keeps a Set of index ids (`state.sel`); main resolves ids to paths itself (`files:describe/trashMany/copyPaths`), so the renderer can never name arbitrary paths. Any change of query (search/filter/folder/sort/view) clears the selection so invisible files can't be deleted.
- Rename keeps the extension fixed, validates the base name per platform, and never overwrites (`file:rename` in main; `fs.rename` overwrites on POSIX so existence is checked first).
- Right-click menus use `App.contextMenu(x, y, items)` (core.js); native menus are not used. Clipboard writes go through main (`clipboard:write`).
- PDF quick view is Chromium's built-in viewer in an `<iframe>` (`frame-src file:` in the CSP); main only validates the path.
- Content search is a SEPARATE step from scanning (user decision): scan first, then "Index contents" runs `indexer.js` in the background. Never run content extraction inside a scan. Scanned PDFs (< 20 extracted chars) are stored as state `empty`; there is no OCR. Old non-Unicode Georgian fonts (AcadNusx/LitNusx) produce Latin gibberish, which is documented on the About page and in the Settings pane. New work on the index must keep `content_fts`/`content_status` in sync with `files` (the `files_cd` trigger deletes them).
- `pdfjs-dist` is used only in `content-worker.js` (legacy build, `import()` from CJS, `task.destroy()` not `document.destroy()`).
- Updates are notification-only (decision): do not add auto-install. The only network access is `updates.js`; it only opens URLs under the repo's GitHub page. Releases are made by pushing a tag equal to the package.json version.
- Icons are cached per extension (main + renderer); renderer shows a colored badge until/unless one loads.

`docs/` holds architecture notes for major things. **Whenever an important change is made (data model, IPC contract, scanner behavior, packaging/CI, security settings, major UI mechanism), update the relevant `docs/*.md` in the same change and add a one-line note in the "Change log" below.** Add a new doc for any new major subsystem.
