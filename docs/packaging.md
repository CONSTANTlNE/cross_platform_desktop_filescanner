# Packaging & CI

- `package.json > build`: NSIS (Windows), AppImage only (Linux; the deb target was dropped on request). Only app files are packaged (`files` whitelist).
- better-sqlite3 is native: `postinstall` runs `electron-builder install-app-deps` so it is compiled for Electron's ABI. Plain `node` cannot load it after that.
- CI: `.github/workflows/build.yml` — matrix `windows-latest`, `ubuntu-latest`; `npm ci` (triggers postinstall) → `npm run dist` → upload `dist/*.exe|*.AppImage`.
- Icons: `build/icon.png` (512) and `build/icon.ico` (16-256) generated by `npm run icons`; referenced by `build.win.icon` / `build.linux.icon`; the PNG is also used at runtime for the window and tray, so it is in `build.files`.
- `build.files` is a whitelist; add new runtime files there.
- `pdfjs-dist` (text extraction in `content-worker.js`; ~38 MB in node_modules). `content-worker.js` and `indexer.js` are in the `build.files` whitelist.
- Runtime deps used by quick view: `mammoth`, `word-extractor`, `xlsx` (installed from `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`; CI `npm ci` needs access to cdn.sheetjs.com). `preview-worker.js` is in the `build.files` whitelist.
- Code signing: intentionally NOT used (decision 2026-11-24). Windows shows the SmartScreen warning once; README explains the click-through. Revisit only if distribution widens (cloud signing ~$10-30/month).
- Releases: pushing a tag `vX.Y.Z` (must equal package.json version) makes the workflow's `release` job publish the installers as a GitHub Release (see `updates.md`).
- Placeholders to replace before release: `appId`, `author`, `linux.maintainer`.
- Open items: Windows NSIS build and a Windows run of the scanner are untested locally; the worker loads from inside the asar (verified on a Linux `--dir` build).
